# Уведомления: этап 5 (часть)

Проверка: `/notifications` для руководителя и `/employee/notifications` для сотрудника.
Колокольчик и пункт меню открывают список текущего пользователя. Статусы
«Непрочитанные», «Прочитанные», «Все», категории, поиск по заголовку, пагинация,
поштучное и групповое прочтение работают в демонстрационном режиме.

## Источники логики

- `KV.Server/src/KV.Server.Application/Inbox/NotificationAppService.cs`:
  получатель `IdentityUserId`, фильтры `Seen`/категория/заголовок, сортировка по
  `CreationTime` по убыванию, пагинация, запись даты `Seen`.
- `KV.Server/src/KV.Server.Web/Pages/Inbox/Index.cshtml.cs`:
  страница требует авторизации; переход к связанной записи отмечает личное
  уведомление прочитанным.
- `KV.Server/src/KV.Server.Web/Pages/Tickets/Details.cshtml.cs` и
  `WriteMessagePreviewModal.cshtml.cs`: старые URL `/tickets/details/:id` и
  `/tickets/detailsMessage/:id` отображаются на новую общую карточку.

Все статусы, включая «Все», всегда ограничены текущим получателем. Прочтение
чужого или неизвестного ID игнорируется; повторное прочтение сохраняет первую дату.
В интерфейсе ссылки принимаются только на существующие локальные карточки, с
сохранением варианта сотрудника. Для уведомлений без заявки доступна отметка
прочтения; неизвестные адреса не превращаются в ссылки.

Демонстрационные категории и уведомления лежат в `entities/notification/model/mock.ts`.
В .NET категории хранятся в базе, поэтому их названия в fixtures не считаются
реальным справочником. Дата прочтения хранится в браузере по `IdentityUserId`.
Счётчик шапки и страница синхронизируются через общий механизм хранения;
при запрете localStorage изменения сохраняются в памяти до обновления страницы.
API/SignalR ещё не подключены, новые уведомления автоматически не приходят.
