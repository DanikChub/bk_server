# Вариант сотрудника: этап 4

Проверка локально: `npm run dev` в `frontend`, затем `/employee/tickets` и
`/employee/tickets/128569`. В верхней панели можно переключить демонстрационный
вариант, сохранив номер открытой заявки. Вариант руководителя остаётся на `/tickets`.
Оба маршрута используют `TicketsPage`, `TicketDetailsPage` и общие виджеты.

## Данные и разрешения

`shared/config/demo-ticket-sessions.ts` содержит **демонстрационные** профили:
руководитель Морозов Иван и сотрудник Макаровский Вадим. Названия разрешений и
проверки перенесены из .NET, но распределение разрешений по ролям хранится в базе
и отсутствует в репозитории. Значения `grantedPolicies` нужно заменить разрешениями
текущей авторизованной сессии при подключении API. Переход по демонстрационному
маршруту не является авторизацией и не должен назначать права в рабочем приложении.

| Действие | Проверка | Источник в `KV.Server/src` |
| --- | --- | --- |
| Список и карточка | `Ticket` + `Ticket.Get` | `KV.Server.Application/Tickets/TicketsAppService.cs` |
| Назначение специалиста, метка, тип, раздел | `Ticket.Edit` | тот же сервис |
| Ответ клиенту, внутреннее сообщение, «Не дозвонились» | `TicketHistory.Create` | `KV.Server.Application/Tickets/TicketHistoryAppService.cs` |
| Чтение переписки | `TicketHistory.Get` | тот же сервис |
| Редактирование сообщения | `TicketHistory.Edit` | тот же сервис |
| Редактирование исходного описания | `TicketHistory.Edit` + `Ticket.Edit` | Razor `Pages/Tickets/Details.cshtml`, `UpdateTicketDescriptionAsync` |
| Удаление заявки | `Ticket.Delete` + роль `admin` или `Руководитель отдела продаж` | `TicketsAppService.cs`, `KV.Server.Web/Pages/Tickets/Details.cshtml` |
| Удаление записи истории | `TicketHistory.Delete` + `Ticket.Delete` | Razor проверяет первое, `DeleteTicketHistoryRecordByIdAsync` — второе |
| Чтение событий | `Event.Get` | `KV.Server.Application/Events/EventAppService.cs` |
| Создание события | авторизованный доступ к карточке | Razor `[Authorize]`; `CreateEventAsync` не содержит именованной проверки |

Razor показывает редактирование собственного сообщения даже без `TicketHistory.Edit`,
но серверный метод всё равно требует это разрешение. Новый интерфейс следует
серверной проверке: владение сообщением само по себе не даёт права редактировать.

Демо-сотруднику предоставлены чтение, ответы, редактирование полей и сообщений,
чтение событий; удаления и администрирования нет. Набор можно изменять для
проверки других конфигураций, включая доступ только для чтения. Проверки присутствуют
в компонентах и обработчиках; API обязан повторять их на сервере.

«Мои заявки» использует идентификатор профиля специалиста, а избранное и настройки
колонок — отдельные ключи этого профиля, как персональное избранное в старом коде.
Остальные вкладки сохраняют фильтрацию старого общего списка: правило «сотрудник
видит только свои заявки» не добавлено, поскольку его нет в этом методе .NET.
Переписка и изменения заявок общие между демонстрационными профилями. Вложения
сохраняют байты только до обновления страницы.

## Дизайн и проверки

Ориентир: файл Figma `za0k2COvn1jIYRdQudeRcl` и общие компоненты этапов 1–3.
На этапе 4 Figma MCP вернула лимит Starter-плана, поэтому отдельные экраны сотрудника
не удалось получить и точно сверить. Компоновка списка без панели специалистов и
состав меню пока требуют визуального сравнения с макетом сотрудника. Не считать
этот этап подтверждённым совпадением с Figma.

Проверки: `npm test`, `npm run lint -- --max-warnings=0`, `npm run build`.
Тесты проверяют матрицу разрешений, отображение допустимых действий, маршруты списка,
персональные ключи и автора сообщений, а также прежние сценарии карточки и списка.
