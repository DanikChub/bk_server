# Перенос клиентского кабинета

Рабочая ветка: `frontend-migration`. Реестр макетов обеих групп — `/screens`.
Он содержит 77 экранов/состояний из структуры Figma, включая вложенные секции.
Статус «Добавлено · на проверку» не означает завершённую приёмку всех состояний.

## Доступные страницы

| Адрес | Назначение |
| --- | --- |
| `/client?design=original` | Главная «Наша версия», Figma `1:733` |
| `/client?design=adapted` | Главная «Адаптированная», Figma `2:6167` |
| `/client/tickets` | Заявки клиента; `tab=work`, `clarification`, `favorites`, `drafts`, `closed` |
| `/client/question` | Вопрос, черновик, вложения, предпросмотр текста |
| `/client/question?state=inactive` | Предупреждение об истёкшем договоре, Figma `1:986` |
| `/client/renewal?id=c2` | Заявка на продление договора, Figma `1:3917` / `1:3950` |
| `/client/profile` | Данные клиента/организации, коллеги, пакеты и помесячные лимиты, Figma `1:1373` |
| `/client/calendar` | Выбор дня и месяца, личные события, Figma `1:776` |
| `/client/login?design=original` | Экран входа `1:890` |
| `/client/login?design=adapted` | Экран входа `2:6757` |
| `/client/ticket?id=165593` | Функциональный просмотр заявки; дизайн карточки ещё требует чтения |
| `/client/library` | Внутренний просмотр демонстрационных материалов; отдельный макет не подтверждён |

Параметр `design` сохраняется при переходах внутри клиентского кабинета.
Для профиля, календаря и продления получен только оригинальный дизайн;
адаптированные варианты ещё не считаются перенесёнными.
Слайды каруселей адаптированной главной ещё не реализованы: из дизайна получены
два видимых баннера, отсутствующие слайды не подменяются вымышленными материалами.
Вкладки и формы управления клиентами, пользователями, договорами и сотрудниками
остаются в реестре как незавершённые.

## Данные и будущий API

`entities/client-portal/model/types.ts` описывает отдельную модель представления
и асинхронный `PortalRepository`. Он не устанавливает URL или схему DTO будущего
Nest API. HTTP-адаптер должен преобразовать серверные DTO в модель представления.
Адаптер передаётся в `PortalProvider`; страницы не обращаются к localStorage или
HTTP напрямую. Предусмотрены загрузка, ошибка, повтор запроса и ошибки мутаций.

`demo-repository.ts` — локальный адаптер. Он не отправляет заявки, сообщения,
данные профиля или логины во внешние сервисы. Экран входа сообщает об отсутствии
сервиса авторизации, демонстрационный кабинет открывается отдельной ссылкой.
Ни маршруты, ни параметры предпросмотра не являются авторизацией.

Будущий сервер обязан определять пользователя и организацию из сессии,
проверять доступ к каждой заявке/вложению, действующий договор и разрешения.
Параметр `state=inactive` нужен только для просмотра макета и не изменяет договор.
Схему авторизации, пагинацию API, хранение файлов и получение справочников
необходимо согласовать с миграцией .NET перед включением HTTP-адаптера.

Демонстрационное состояние сохраняется отдельно под `demo-client-graf`.
При недоступном localStorage используется память. Метаданные вложений сохраняются,
содержимое доступно до перезагрузки страницы; после неё интерфейс объясняет,
почему файл недоступен. Лимит вложений — 50 МБ на сообщение/вопрос.
Фото сохраняется локально (PNG/JPEG/WebP, до 5 МБ); это также часть API-контракта.
Тексты материалов и ответы — fixtures, не актуальные юридические консультации.
Будние дни календаря не выдаются за официальный производственный календарь.

## Проверка

Сборка: `node node_modules/next/dist/bin/next build`.
Тесты: `node --test tests/*.test.mjs`.
Lint: `node node_modules/eslint/bin/eslint.js src tests next.config.ts --max-warnings=0`.
`tests/client-portal.test.mjs` проверяет черновики, переход к отправленной заявке,
валидацию вложений, ограничения ответов/оценок, отсутствующие записи и продление.
Windows-пути в загрузчике UI-тестов исправлены через `fileURLToPath`.
