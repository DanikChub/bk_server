# Демонстрационный стенд

Подготовка: 18 ноября 2026. Цель — показать текущий прогресс переноса, не приёмка
полной функциональной эквивалентности KV.Server.

Работающий адрес: https://consulting-lk.103-74-92-127.sslip.io
Вход: `/client/login`. Это технический DNS-адрес, связанный с IP сервера.
Развёрнут 18 ноября 2026. HTTPS-сертификат Let's Encrypt выпущен через Caddy.
Запущены app, worker, PostgreSQL, RabbitMQ и reverse proxy.
Начальное наполнение: 16 заявок, 2 организации, 2 договора, переписка, внутренние
записи, S3-вложения, события, лимиты, шаблоны ответов и уведомления. Сквозная
проверка дополнительно создала заявку с названием «ДЕМО: сквозная проверка ...».

Все проверки `verify-showcase.mjs` прошли на публичном HTTPS-адресе: шесть аккаунтов,
grants, изоляция организаций, скрытая история, реальная загрузка/скачивание S3,
ZIP, PDF, XLSX, multipart-создание заявки, ответ специалиста, возобновление,
избранное, уведомления и выход. Кабинеты клиента/специалиста и карточки заявок
дополнительно проверены через браузер.

При проверке обнаружена и исправлена ошибка упаковки PDFKit в standalone Docker:
PDFKit/fontkit теперь разрешаются как внешние Node.js-пакеты с необходимыми данными.

## Аккаунты

| Логин | Организация при входе | Назначение |
| --- | --- | --- |
| demo.admin | Пусто | Главный администратор |
| demo.head | Пусто | Руководитель отдела продаж |
| demo.manager | Пусто | Менеджер Отдела Продаж |
| demo.specialist | Пусто | Специалист |
| demo.client | Альфа | Клиент первой организации |
| demo.other | Вектор | Клиент второй организации, проверка изоляции |

Пароли генерируются отдельно и не хранятся в Git. Аккаунты и роли являются
демонстрационной конфигурацией на основе названий и проверок старого сервера.
Не считать эти наборы grants согласованной матрицей production-прав.

На исходном рабочем компьютере приватная инструкция с паролями:
`database/.local/showcase-access.md` (игнорируется Git). Начальные пароли после
наполнения удалены из окружения app/worker. Если доступы передаются на другое
устройство, нужен отдельный защищённый перенос этого файла — git clone их не даёт.

## Сценарий показа

1. В приватном окне войти `demo.client`, организация `Альфа`. Показать профиль,
   список и статусы заявок, избранное, черновик, договор и списания.
2. Открыть заявку с перепиской и скачать тестовое вложение. Создать новую заявку
   с файлом, отправить сообщение. Все организации, ФИО и документы синтетические.
3. В другом профиле браузера войти `demo.specialist` без организации. Открыть ту
   же заявку, ответить, сменить статус и показать внутреннюю заметку.
4. Вернуться в кабинет клиента: ответ виден, внутренняя заметка скрыта. Ответить
   на закрытую заявку и показать её возобновление по исходной логике.
5. Войти менеджером/руководителем: показать клиентов, договоры, уведомления и
   выгрузки. Войти администратором для создания сотрудников и пользователей.
6. Войти `demo.other`, организация `Вектор`: заявки первой организации отсутствуют,
   переход по известному чужому номеру запрещён.

Рабочие данные не загружаются. Библиотека/новости без внешних доступов могут быть
недоступны. Полные административные экраны ролей, исторический импорт и некоторые
функции Identity ещё не перенесены; подробнее `backend-runtime.md` и `HANDOFF.md`.

## Обслуживание

Сервер: `103.74.92.127`, каталог `/opt/consulting-lk`.
Команды из этого каталога:

```bash
docker compose -f compose.yaml -f deploy/compose.showcase.yaml --project-directory . ps
docker compose -f compose.yaml -f deploy/compose.showcase.yaml --project-directory . logs --tail=100 app worker proxy
```

Конфигурация находится в `.env` с правами 600, содержит секреты, не публиковать.
PostgreSQL и RabbitMQ не публикуют порты наружу. HTTPS обслуживает Caddy;
его данные сертификатов и PostgreSQL хранятся в постоянных Docker volumes.
Команда `down -v` уничтожает данные, для обычного перезапуска её не использовать.

Сервер малый: около 1 ГБ RAM и 14 ГБ диска; добавлено 2 ГБ swap. В showcase override
заданы ограничения памяти контейнеров. Это стенд для демонстрации с небольшим
числом одновременных пользователей, не производственная конфигурация.

Начальное наполнение: `frontend/scripts/seed-showcase.ts` с явным
`SHOWCASE_SEED=true` и `SHOWCASE_PASSWORDS` (JSON с шестью паролями).
Маркер `NextCache/showcase.seed.v1` предотвращает повторное наполнение.
Использовать только в отдельной демонстрационной БД.

Проверка: `SHOWCASE_URL=https://... node frontend/scripts/verify-showcase.mjs PATH_TO_PRIVATE_PASSWORDS_JSON`.
Она проверяет реальные API, S3, роли, документы и создаёт тестовую заявку.
