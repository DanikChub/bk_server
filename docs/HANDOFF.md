# Продолжение работы с другого устройства

Обновлено: 17 ноября 2026. Репозиторий: DanikChub/bk_server.

## Задача пользователя

Полностью перенести прикладную логику локального `KV.Server` на TypeScript,
Next.js, PostgreSQL, Drizzle/pg, S3 и отдельный worker с RabbitMQ. Уже выполненный
перенос таблиц не заменяет перенос поведения. Пользователь разрешил необходимые
действия и просит работать самостоятельно. Полнота переноса пока не достигнута.

## Что сохранено

- `frontend/src/server`: авторизация, совместимость ASP.NET Identity хешей,
  TOTP, сессии, tenant-изоляция, роли/grants, организации, пользователи и сотрудники,
  договоры/пакеты/лимиты, заявки/история/назначения/избранное/рейтинг, события,
  уведомления, истории, статистика, PDF/XLSX, файлы и интеграционные адаптеры.
- `frontend/src/app/api`: настоящие серверные маршруты. По умолчанию интерфейс
  использует API. `NEXT_PUBLIC_DATA_MODE=demo` включает прежние демоданные.
- Файлы и создание заявки/ответа объединены multipart-командой с транзакцией
  и компенсацией S3 при откате. Сохранены старые ключи объектов.
- Отдельный worker: outbox, повторные попытки, расписание активности клиентов,
  публикация/приём tenant-событий RabbitMQ и дедупликация входящих сообщений.
- `database/migrations/004_next_runtime.sql`: добавочные runtime-таблицы.
  Исходные `database/init.sql`, функции и триггеры сохранены.
- `.env.example`, Dockerfile, compose, bootstrap и воспроизводимые проверки.

## С чего начать на новом устройстве

1. Клонировать репозиторий и получить последний commit `main`.
2. Прочитать `frontend/AGENTS.md`, `docs/backend-runtime.md`,
   `docs/backend-migration-scope.md` и `docs/admin-and-roles.md`.
3. `cd frontend`, `npm ci`. Для контейнеров предусмотрен Node.js 24.
4. Создать локальный `frontend/.env.local` по `.env.example`, указать собственные
   подключения. Секреты и рабочая БД через GitHub не передаются.
5. На базе с перенесённой схемой выполнить `npm run db:migrate`, затем
   `npm run db:bootstrap`. Пустая БД требует предварительного `database/init.sql`.
6. Запустить `npm run dev` и отдельно `npm run worker`.

Рабочий стенд заказчика не развёрнут. Production БД не переключалась.
На новом устройстве нет автоматически перенесённых локальных `.env` и данных.

## Проверено

На 15 ноября 2026 прошли production build, TypeScript, ESLint, 45 frontend-тестов,
19 backend-тестов на отдельном PostgreSQL 17 и HTTP-проверка production-сервера
(вход, сессии, Origin, валидация, права клиента, скрытая история, PDF, выход).
S3 в интеграционных тестах — локальный HTTP fake. Реальные внешние подключения
не проверены. Compose config проверен, сборка/запуск контейнеров не проверены.

Повторение: из frontend `npm run typecheck`, `npm run lint`, `npm test`,
`npm run build`; из корня на Windows с PostgreSQL 17:
`./database/tools/verify-backend.ps1 -Port 55446 -WithHttp`.
Последний скрипт использует отдельный временный кластер и останавливает его.
