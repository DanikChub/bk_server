# Новый сервер

Реализация: `frontend/src/server`. HTTP: Next.js Route Handlers в Node.js;
PostgreSQL через параметризованные запросы `pg`, описание 69 таблиц через Drizzle.
Схемой управляют SQL-миграции, включая существующие функции и триггеры.
React получает данные через `/api/v1`; секреты, SQL и S3 находятся на сервере.

## Локальный запуск

Из `frontend`:

```powershell
npm ci
# Настроить frontend/.env.local по корневому .env.example.
# DATABASE_URL должен указывать на PostgreSQL с уже перенесённой схемой.
npm run db:migrate
npm run db:bootstrap
npm run dev
```

В отдельном процессе из `frontend`: `npm run worker`.
Bootstrap создаёт статусы и роль администратора. Новый администратор создаётся
только при явном задании `BOOTSTRAP_ADMIN_USERNAME` и `BOOTSTRAP_ADMIN_PASSWORD`;
существующие пользователи и пароли не перезаписываются.
Не выполнять `database/init.sql` повторно поверх рабочей базы.

Для production: `npm run build`, затем `npm start` и отдельный worker.
Нужен HTTPS reverse proxy, `APP_URL` с точным публичным origin и резервное
копирование БД/хранилища. Для контейнеров подготовлен `compose.yaml`:

```powershell
# Заполнить корневой .env по .env.example, включая пароли и DATABASE_URL.
docker compose up -d --build
docker compose run --rm worker npm run db:migrate
docker compose run --rm worker npm run db:bootstrap
```

Compose использует новые volumes. На пустом volume схема и runtime-миграция
применяются автоматически; на существующем нужен явный `db:migrate`.
Внутри compose адрес БД — `postgres:5432`, брокера — `rabbitmq:5672`.
S3 подключается отдельно четырьмя настраиваемыми buckets.
Проверена конфигурация Compose; запуск Docker-образов ещё не проверен.

## Модули и маршруты

Все маршруты `/api/v1` требуют сессии. Права проверяются заново по текущим grants
БД, tenant и владению записью. Изменяющие запросы проверяют Origin; тела ограничены
по размеру, параметры сортировки выбираются из разрешённого списка.

| Маршрут | Возможности |
| --- | --- |
| `/api/auth/login`, `/logout`, `/session` | Сессии, старые Identity V2/V3 хеши, блокировка, TOTP, обязательная смена пароля |
| `/api/v1/tickets` | Заявки, фильтры, пагинация, собственные черновики |
| `/tickets/:id/...` | Ответы, внутренние записи, статусы, исполнители, тип/раздел, лимиты, избранное, рейтинг, прочтение, теги, PDF |
| `/tickets/:id/files` | Вложения, скачивание отдельного файла и ZIP |
| `/tickets/:id/history/:historyId` | Редактирование и удаление записей |
| `/contracts` | Договоры, пакеты с отдельными датами, лимиты, статистика, теги |
| `/customers` | Организации, реквизиты, контакты, менеджеры, журнал, статистика, удаление связанных профилей и отзыв доступа |
| `/users`, `/employees`, `/roles` | Identity, профили, роли/grants, активность и пароли |
| `/catalogs/:name` | Разрешённые справочники и шаблоны ответов |
| `/events`, `/notifications` | События и персональные уведомления |
| `/stories`, `/assets/stories`, `/profile/avatar` | Истории, слайды и изображения |
| `/portal` | Составной кабинет клиента, профиль, события, запрос продления договора |
| `/reports/:kind` | XLSX заявок, договоров, организаций, профилей и статистики |
| `/content`, `/legacy-content`, `/external-resource` | Адаптеры контентных провайдеров и внешней авторизации |
| `/jobs` | Очередь и повтор выполнения задач для администратора |
| `/api/health`, `/api/ready` | Живость процесса и готовность базы |

Точные допустимые методы/поля находятся в route.ts и Zod-схемах соответствующего
модуля. Это новый контракт API, а не побайтовое воспроизведение автогенерируемого ABP API.
Старые `/custom-account/AuthorizeResource` и `/SignOff` имеют адаптеры.

## Файлы, транзакции, worker

Сохранены ключи объектов `host/{id}` и `tenants/{tenantId}/{id}`.
Загрузка проверяет доступ к заявке/сообщению. Multipart-команды с полем `data`
(JSON) и `files` объединяют создание заявки/ответа/продления и файлов в одну
транзакцию; при откате удаляются загруженные объекты без закоммиченных метаданных.
Скачивание потоковое, ZIP собирается на сервере. Лимит загрузки — 50 МБ.

Worker обрабатывает PostgreSQL outbox с блокировкой и повторными попытками,
пересчитывает активность организаций по расписанию, публикует события RabbitMQ,
при настроенной входящей очереди принимает события tenant с дедупликацией.
Неизвестные/некорректные сообщения сохраняются для разбора оператором.
Календарь кешируется в PostgreSQL; расписание использует Europe/Moscow по умолчанию.

## Проверки и границы готовности

```powershell
# Из корня, нужен установленный PostgreSQL 17:
.\database\tools\verify-backend.ps1 -Port 55445 -WithHttp
# Из frontend:
npm run typecheck
npm run lint
npm test
npm run build
```

Скрипт создаёт отдельный временный кластер, применяет исходную схему и новую
миграцию, выполняет интеграционные тесты и останавливает кластер. Не использует
рабочую БД. S3 в этих тестах заменён локальным HTTP-сервером.

Проверено 2026-11-15: production build, TypeScript, ESLint, 45 существующих
frontend-тестов и 19 backend-тестов прошли. Отдельная HTTP-проверка production
сервера прошла: вход, сессии, CSRF, валидация, tenant-права, скрытая история,
PDF и отзыв сессии при выходе. Повторное применение runtime SQL также проверено.

Перенос ещё нельзя называть полностью эквивалентным старому серверу:

- Реестр `legacy-operations.json` содержит 495 объявленных методов; индивидуальная
  сверка всех методов, Razor/JS и унаследованных ABP API ещё не завершена.
- Старый SQL Server importer `Migration/KvMigrationService` ещё не перенесён.
  Он отличается от уже выполненного переноса схемы PostgreSQL.
- Собственные сессии не реализуют OpenIddict/OAuth/OIDC protocol endpoints.
  Внешний JWT-переход реализован отдельно; email MFA/recovery не реализованы.
  Аккаунты без поддерживаемого TOTP-провайдера получают явную ошибку.
- PDF имеет новое текстовое представление; точное старое печатное оформление
  и все административные интерфейсы ещё требуют сверки.
- Реальные S3, RabbitMQ, производственный календарь и контентные провайдеры
  требуют проверки с конфигурацией установки. Секреты из исходников не копировались.
- Восстановление старого обратимо зашифрованного пароля требует явно заданных
  параметров ABP encryption. Новое хранение обратимых паролей по умолчанию выключено.
- Production переключение и миграция рабочих данных этим изменением не выполнены.

Исправленные отличия: черновики закрыты от чужих пользователей даже при старом
`IsPublic=true`; удаление организации явно отзывает доступ; обновление активности
обрабатывает всю выборку; календарь поддерживает переход между годами.
