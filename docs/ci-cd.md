# Автоматическое обновление стенда

Push в main запускает `.github/workflows/deploy.yml`. Сначала GitHub проверяет
TypeScript, ESLint, frontend-тесты, backend-тесты на отдельной PostgreSQL 17,
production build и HTTP-сценарии. Pull request запускает только проверки.

После успешных проверок Actions подключается к 103.74.92.127 выделенным SSH-ключом.
Ключ разрешает только команду `deploy <SHA>`: интерактивный вход, SFTP и проброс
портов отключены. Личный SSH-ключ пользователя не используется. Отпечаток сервера
закреплён в DEPLOY_KNOWN_HOSTS; StrictHostKeyChecking включён.

Сервер получает этот commit из фиксированного публичного репозитория
DanikChub/bk_server, проверяет принадлежность истории main и собирает app/worker
через Docker Compose. Последовательные деплои блокируются flock; текущий деплой
не прерывается новым push. Окружение GitHub `showcase` допускает только main.

Перед изменениями выполняется pg_dump в закрытый каталог backups. После сборки
применяются добавочные миграции и перезапускаются app/worker. Проверяются локальный
readiness и публичный HTTPS. При ошибке возвращаются предыдущие Docker-образы и
compose-файлы. Автоматического восстановления БД из дампа нет: миграции должны
оставаться обратно совместимыми; дамп предназначен для осознанного восстановления.

Рабочий каталог: /opt/consulting-lk. Закрытый .env, SMTP/S3, тома БД, RabbitMQ и
сертификатов не передаются через GitHub. Удалённые из Git файлы frontend также
удаляются при синхронизации исходников; приватные env и runtime-каталоги исключены.
Последний успешно развёрнутый SHA записывается в backend-revision.

Повторный запуск: GitHub → Actions → Verify and deploy main → Run workflow (main).
Логи сборки и развёртывания доступны в соответствующем запуске Actions.

Перед сборкой удаляются только неиспользуемые образы без тегов и ограничивается
кеш Docker до 512 МБ. Текущие контейнеры и образы latest/rollback сохраняются.
