Дополнительно перенесены создание от имени клиента, отдельная переписка
TicketMessages с уведомлением, календарь сотрудника по CreatorId независимо от
tenant заявки, исходные колонки XLSX и метаданные печатной заявки. PDF содержит
данные и авторов истории, но его верстка не повторяет прежний HTML-макет.

Восстановление пароля и email MFA используют одноразовые хешированные токены,
срок действия и SecurityStamp. Смена пароля отзывает сессии. Письмо доставляет
worker через SMTP; реальный провайдер почты ещё не настроен. Эти функции не
заменяют протокольный сервер OpenIddict.

`005_runtime_statistics.sql` устанавливается поверх существующей схемы;
`006_account_recovery.sql` добавляет таблицу токенов. Baseline `init.sql` сохранён.
После резервного копирования и миграции существующих данных: `npm run db:statistics`
пересчитывает договоры по одному с транзакцией. Исправления намеренно исключают
soft-deleted записи и умножение списаний на историю настроек. Прошлые MaxCount
сохраняются, текущий месяц получает актуальное значение.

Конкурентный тест выявил конфликт FOR UPDATE с KEY SHARE внешнего ключа.
Замена на FOR NO KEY UPDATE сохраняет последовательность пересчётов и устраняет
этот конфликт. Повторы транзакций при 40001/40P01 ограничены тремя попытками.

Проверено: production build, TypeScript, ESLint, 45 frontend-тестов, 36 backend-тестов
и HTTP-проверка production-сервера на новой отдельной PostgreSQL 17 (включая PATCH,
уведомление после ответа, каталог разрешений и страницы восстановления). S3 в этих тестах —
локальный HTTP-сервер; настоящие S3/HTTPS проверяются отдельным verify-showcase.

Открыто: реальный OIDC/внешний SSO, исторический SQL Server импорт и контроль рабочих
данных/файлов, реальный SMTP, недоступные контентные провайдеры, полная матрица
эффективных grants всех старых операций, большие объёмы и аварийные сценарии.
Figma и соответствие экранов требуют отдельной UI-проверки.
