Дополнительно перенесены создание от имени клиента, отдельная переписка
TicketMessages с уведомлением, календарь сотрудника по CreatorId независимо от
tenant заявки, исходные колонки XLSX и метаданные печатной заявки. PDF содержит
данные и авторов истории, но его верстка не повторяет прежний HTML-макет.

Восстановление пароля и email MFA используют одноразовые хешированные токены,
срок действия и SecurityStamp. Смена пароля отзывает сессии. Письмо доставляет
worker через SMTP; реальный провайдер почты ещё не настроен. Эти функции не
заменяют протокольный сервер OpenIddict.

`005_runtime_statistics.sql` устанавливается поверх существующей схемы;
`006_account_recovery.sql` добавляет таблицу токенов. Baseline `init.sql` сохранён.
После резервного копирования и миграции существующих данных: `npm run db:statistics`
пересчитывает договоры по одному с транзакцией. Исправления намеренно исключают
soft-deleted записи и умножение списаний на историю настроек. Прошлые MaxCount
сохраняются, текущий месяц получает актуальное значение.

Конкурентный тест выявил конфликт FOR UPDATE с KEY SHARE внешнего ключа.
Замена на FOR NO KEY UPDATE сохраняет последовательность пересчётов и устраняет
этот конфликт. Повторы транзакций при 40001/40P01 ограничены тремя попытками.

Проверено: production build, TypeScript, ESLint, 45 frontend-тестов, 36 backend-тестов
и HTTP-проверка production-сервера на новой отдельной PostgreSQL 17 (включая PATCH,
уведомление после ответа, каталог разрешений и страницы восстановления). S3 в этих тестах —
локальный HTTP-сервер; настоящие S3/HTTPS проверяются отдельным verify-showcase.

Развёрнуто на `https://consulting-lk.103-74-92-127.sslip.io` (код 6d95b6c,
включая дополнительные DTO/списания ниже; повторная HTTPS/S3-проверка прошла).
Перед миграцией сделан pg_dump в закрытый каталог сервера `backups`.
Миграции 004–006 применены; пересчитаны оба демонстрационных договора.
Шесть аккаунтов и настоящий S3 прошли verify-showcase, включая новые PATCH,
историю и уведомление клиенту. Все контейнеры работают, фоновые задания завершены.
Календарь isdayoff проверен через HTTPS API стенда на ноябре 2026: 30 дней,
20 рабочих, 4 ноября нерабочий. Это явный альтернативный источник дат;
старый production-calendar сохранён и требует оплаты подписки владельцем.

Пользователь выбрал Gmail как временного отправителя и отдельно подтвердил
передачу пароля приложения на свой демосервер и тестовое письмо на собственный
адрес. Секрет перенесён в закрытый `.env` (600), временный файл сервера удалён.
Настройки не включены в Git. Первые IPv4-проверки портов дали timeout;
последующая настоящая SMTP-проверка прошла: аутентификация подтверждена,
Google принял одно согласованное тестовое письмо. App/worker получают настройки
после пересоздания контейнеров. Доставка во входящие ещё требует проверки получателем.

Открыто: реальный OIDC/внешний SSO, исторический SQL Server импорт и контроль рабочих
данных/файлов, недоступные контентные провайдеры, полная матрица
эффективных grants всех старых операций, большие объёмы и аварийные сценарии.
Figma и соответствие экранов требуют отдельной UI-проверки.

Дополнительная сверка TicketHoursSpentHistoryAppService, NewsAppService и
PostsAppService: GET `/api/v1/tickets/:id/spent` возвращает суммы по типу ограничения,
с правильной настройкой договора и фильтром внутренней истории клиента. Создание
списания возвращает ConstraintTypeName. Старые новости преобразуют вложенный
thumbnail в CoverUrls; статьи Posts дополнены прежним плоским DTO `items` при
сохранении `data` для нового интерфейса. `totalCount` использует meta.pagination.total,
а не длину одной страницы. Добавлены проверки пагинации/формата/tenant: 38/38 backend.
